# P2.2 Review Decision

Date: 2026-06-20
Decision: Accept with applied changes

## Determinism Decision

The canonical hash represents the portable `ModelInventory`, not the full execution envelope.

- `ModelInventory` includes stable source SHA-256 and size plus extracted model semantics.
- `InventoryRun` contains registered path, filename, and complete runtime provenance.
- Absolute source and runtime paths are recorded but excluded from canonical inventory bytes.
- Equivalent inventories with different envelope paths must produce the same semantic hash.
- Exact semantic hashes may be used only after schema/runtime versions and input identity are controlled.

## Applied Before Checkpoint

- Added `SourceIdentityRecord` for portable source identity.
- Added `InventoryRun` with source/runtime provenance and identity-consistency validation.
- Changed `inspect_model()` to return `InventoryRun`.
- Added a test proving different machine paths preserve the semantic inventory hash.
- Clarified that `VersionTranslator` may upgrade the in-memory model without mutating the source file.
- Removed the machine-specific observed hash from evidence.

## Accepted As Implemented

- Direct linear SDK traversal.
- SHA-256 before/after as the no-on-disk-mutation guarantee.
- Handle-based bidirectional relationship maps.
- SWIG optional conversion through `is_initialized()` and `get()`.
- Construction-time relationship backfill through validated records.
- Nullable missing relationships as inventory facts rather than extraction failures.

## Deferred

- Orphan-surface coordinate representation and fixture: P2.3/P3.
- Missing story/zone fixtures and structured findings: P2.3/P3.
- Relationship backfill micro-optimization: only after measured pressure.
- Writing/releasing artifacts and registered-path policy: Simulation OS adapter.
- East Gate acceptance: pending its first OSM.
