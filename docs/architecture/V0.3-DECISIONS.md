## Orphan relations (fact, policy approved by Roberto)

- Typed OpenStudio accessors that return a related object directly segfault when the relation is
  absent: 74 (type, accessor) pairs over 65 fields in the corpus types
  (`validators/_fatal_references.py`, derived by `v0.3-evidence/blank_probe.py`). 31 call sites in
  17 curated functions use such accessors without a guard.
- `StandardsInformation:Material.material()` dies on 15 of 31 models, including FPM4 v9/v10 Proposed
  and the repo fixture `R2F-Office-Hub.osm`; no curated function calls it today.
- An empty Optional `.get()` raises `SystemError` or leaves an exception set that surfaces later.
- A reference to a non-existent handle is cleared by OpenStudio on load (logged), so after loading it
  looks like an empty reference. Text-level detection (`v0.3-evidence/ref_audit.py`) is outside v0.3.

Policy:

1. The generic reader uses only `getString`/`getTarget` (done, enforced by a contract test).
2. Curated functions never dereference a relation through a typed accessor without checking the
   field target first (pending, item 2).
3. Optionals are unwrapped only through `openstudio_toolkit._sdk.opt` (pending in `osm_objects`,
   item 2; contract test `test_no_bare_optional_get_in_osm_objects`).
4. Orphans are reported as `integrity.reference.absent` findings with `object_type="model"`; the
   `FindingObjectType` schema is not widened (done).

## Item 2: pattern and migration (session 2026-10-27)

Tests: `tests/osm_objects/test_dataframe_functions.py` (per function, found by introspection: empty
family has columns; fixtures with objects give the same columns; every `FATAL_WHEN_ABSENT` field blanked
on the fixtures, one subprocess per function, must not raise or die). `PENDING_MODULES` lists modules
not migrated yet (xfail, non-strict). Fixture for families no other fixture had (VRF, gas/steam/other
equipment, building units, exterior fuel/water, output variables): `tests/resources/extra_families.osm`,
built by `tests/resources/make_extra_families.py`.

Pattern (fact, verified by comparing every cell of every migrated function against d86d2c2 (before item 2) on
`small_office`, Office Hub and `extra_families` with `v0.3-evidence/compare_values.py`):

- Columns: a module-level `X_COLUMNS` tuple passed to `build_dataframe(..., columns=X_COLUMNS)`.
- Relations: keep typed accessors that return an Optional, through `_sdk.optional_name`. They return
  values inherited from default schedule/construction sets when the field is empty (e.g. 272 of 278
  surfaces in Office Hub take their construction from a set); reading the field instead loses them.
  Read through the field target (`_sdk.related_name`) only where the accessor returns the object
  directly and segfaults when empty (`FATAL_WHEN_ABSENT`). This refines policy 2 above.
- Topology fields that point to `OS:Connection` need one more hop (`thermal_zones._zone_air_node_name`).
- `FATAL_WHEN_ABSENT` misses combined cases: `ScheduleRuleset.summer/winterDesignDaySchedule()` fall
  back to the default day and segfault when both fields are empty (`schedules._design_day_schedule_name`).
- Node fields of 7 HVAC functions removed (Roberto's decision): chiller, coil cooling water, coil heating
  water, coil heating gas, air-to-air HX, AC VRF, and coil heating DX VRF. The accessors do not exist in
  OpenStudio 3.11 (AttributeError on Office Hub / `small_office`). The VRF heating coil fields exist in the
  IDD but were empty in all 104 coils of FPM4 Proposed and 65 of the VRF component library; the generic
  reader still exposes them.
- Construction layers: fixed columns `Layer 1`..`Layer 10` (Roberto, 2026-10-27). OpenStudio 3.11 refuses
  an 11th layer; the most seen in 400 local models is 7.

- `FATAL_WHEN_ABSENT` gained 5 pairs from a targeted probe on fresh objects (types absent from the
  corpus): `OS:Fan:OnOff` speed-ratio curves and `OS:ZoneHVAC:UnitHeater` fan, coil and availability
  schedule. Seven other direct `availabilitySchedule()` reads (fans, water/gas coils, fan coil) return the
  always-on schedule when empty and are safe.
- Zone equipment lists: at least 5 equipment slots (most seen per zone in 400 local models: 4; no
  OpenStudio limit), more if a zone has more. Same rule as construction layers.

State: item 2 implemented. All 21 modules migrated, every cell compared against d86d2c2 on the three
fixtures (identical, or an old crash now works); `PENDING_MODULES` is empty and both contract invariants
are "implemented". Delegation brief kept for later work of the same kind:
`v0.3-evidence/item2_delegation_brief.md`.
